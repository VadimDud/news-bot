# Fibonacci Retracement (fib_pullback) — инструкция по использованию и торговле

Стратегия трендового продолжения по Фибоначчи-откату. Контейнер `moex-trader`
сканирует watchlist на **4-часовых барах** (ресемпл из 1h) несколько раз в день
после закрытия каждого 4h-бара и присылает в Telegram готовые сигналы, уже
настроенные под характер каждой бумаги (направление, таймфрейм, параметры).
Сделки можно совершать вручную по сигналу (основной путь) либо через
автоматическую live-торговлю (опционально).

---

## 1. Как работает стратегия

Стратегия ловит **продолжение тренда после отката**:

1. Бумага делает импульс (swing low → swing high для лонга, обратно — для шорта).
2. Цена откатывает в зону **50–61.8 %** этого импульса (зона Фибо).
3. Если откат подкреплён конфлюэнцией (зона + свечной паттерн + RSI) и тренд
   сохраняется — сигнал на вход **по направлению тренда**.
4. **Стоп** — за экстремум импульса (swing low для лонга / swing high для шорта).
5. **Тейк** — 0 % (противоположный экстремум), т.е. цель — полный возврат к
   экстремуму, от которого откатывали.

**Направление задаётся per-ticker** (`direction`):
- `1` — только лонг
- `-1` — только шорт
- `0` — оба направления (по умолчанию для бумаг без настроек)

**Таймфрейм задаётся per-ticker** (`timeframe`): `4h` по умолчанию, `1day` для
бумаг, на которых 4h не работает.

## 2. Как читать сигнал в Telegram

Сканер присылает сообщение вида:

```
📉 СИГНАЛ ПРОДАЖА — MTSS
Фибоначчи-ретрейсмент (трендовое продолжение) • 19:32 01.09.2026 МСК
Цена: 165.20 ₽
Импульс: swing low 140.50 ₽ → swing high 180.00 ₽ (+28.1%)
Откат вверх: ~160.25 ₽ — в премиальной зоне 50–61.8 %
Тренд вверх: нет | RSI: 72.3 | Факторов: 2

Уровни Фибо (откат вверх, цель — swing low):
38.2%      : 164.91 ₽
50.0%      : 160.25 ₽
61.8%      : 155.59 ₽
78.6%      : 148.96 ₽
0% (цель)  : 140.50 ₽

План: шорт по завершении отката вверх в зону 50–61.8 % (конфлюэнция
зона+свеча+RSI). Стоп за swing high, цель — 0 % (swing low).
⚠️ Не является индивидуальной инвестиционной рекомендацией.
```

Что означает каждая строка:

- **Импульс** — последний завершённый ход рынка (для лонга: swing low → swing high).
- **Откат / зона** — где цена находится сейчас относительно импульса; сигнал
  возникает, когда цена в зоне 50–61.8 %.
- **Тренд вверх** — фильтр направления: для шорта должно быть «нет», для лонга «да».
- **Факторов** — число сработавших условий входа (зона + свечной паттерн + RSI).
- **Уровни Фибо** — ориентиры цен; **0% (цель)** — куда ожидается движение.
- **Стоп/цель** — за экстремум импульса.

**Дедупликация**: сигнал по бумаге уходит один раз на уникальную пару
swing low → swing high. Повторный сигнал придёт только после нового импульса.

## 3. Настройка сканера под бумагу

Веб-дашборд: `http://<host>:8081` → меню **«Fib-сканер»**.

Приоритет параметров (чем выше, тем приоритетнее):

1. **Сохранённое в БД** (страница «Fib-сканер») — задаётся вручную;
2. **`TICKER_OVERRIDES`** в коде (`app/strategies.py`) — отобранные перебором;
3. **Глобальный конфиг** `TRADER_FIB_*` из `.env`.

Как задать настройку для бумаги:

1. Откройте `/fib`, введите тикер (например `LKOH`).
2. Выберите направление: `-1` (шорт) / `1` (лонг) / `0` (оба).
3. Опционально вставьте JSON-параметры, например:

```json
{"swing_bars": 10, "trend_period": 200, "confluence_min": 2,
 "fib_in_low": 0.5, "fib_in_high": 0.618, "rsi_overbought": 75}
```

4. «Сохранить». Сигналы по этой бумаге пойдут уже с этими параметрами.
5. Кнопка «Сбросить» удаляет настройку — бумага вернётся к кодовым оверрайдам.

**Глобальные параметры** (для всех бумаг без настроек) задаются в `.env`
(применяются после перезапуска контейнера):

```
TRADER_FIB_SWING_BARS=10
TRADER_FIB_FIB_IN_LOW=0.50
TRADER_FIB_FIB_IN_HIGH=0.618
TRADER_FIB_TREND_PERIOD=200
TRADER_FIB_CONFLUENCE_MIN=2
TRADER_FIB_RSI_OVERSOLD=40
TRADER_FIB_USE_HTF=1
TRADER_FIB_TIMEFRAME=4h
TRADER_FIB_EXTRA_SCANS=21:00,01:00,05:00,09:00
```

Время скана: `TRADER_FIB_SCAN_HOUR/MINUTE` (основное, по умолчанию 16:30 UTC ≈
19:30 МСК) + `TRADER_FIB_EXTRA_SCANS` — дополнительные времена (UTC) после
закрытия 4h-баров. `TRADER_FIB_RUN_ON_STARTUP=true` — прогон сразу при старте.
4h-свечи докачиваются автоматически фоновой задачей (для всех бумаг, кроме
тех, что работают на 1day — напр. SBER/MTSS).

## 4. Как проверить стратегию (бэктест)

### Через веб-дашборд

1. `http://<host>:8081` → главная «Бэктест».
2. Заполните форму:
   - **Тикер** — например `MTSS` (можно несколько через запятую);
   - **Таймфрейм** — `4h` (основной ТФ сканера) или `1day`;
   - **Стратегия** — «Фибоначчи ретрейсмент (трендовое продолжение)»;
   - **Даты** — например 2025-08-01 → сегодня (4h данные ~400 дней);
   - **Капитал** — 100000, **Комиссия** — 0.0005.
3. Параметры формы подтянутся автоматически; для шорта поставьте
   **«Направление» = -1**, `confluence_min` = 1, `min_rr` = 1.0.
4. «Запустить бэктест» → прогресс-бар → результат.

Как читать результат:
- **Доходность** (`total_return_pct`) — итоговый процент за период;
- **Win rate** — доля прибыльных сделок;
- **Profit Factor** — отношение суммарной прибыли к суммарному убытку (>1.5 — хорошо);
- **Expectancy** — средний результат на сделку;
- **Max просадка** — максимальная просадка капитала;
- **Сделки** — таблица входов/выходов.

### Через командную строку

```bash
PYTHONPATH=trading_moex python3 trading_moex/scripts/backtest_fib_pullback.py \
    --tickers MTSS --periods 1day --direction -1

# Перебор параметров (grid) с выводом в CSV:
PYTHONPATH=trading_moex python3 trading_moex/scripts/backtest_fib_pullback.py \
    --ticker MTSS --period 1day --direction -1 --grid --csv results.csv

# Двухступенчатый per-ticker перебор (быстрый симулятор + верификация бэктестером):
PYTHONPATH=trading_moex python3 trading_moex/scripts/grid_fib_pullback.py \
    --tickers MTSS,GAZP --direction -1 --top 5
```

`--direction`: `1` — лонг, `-1` — шорт, `0` — оба.

## 5. Как совершать сделки (основной путь — вручную по сигналу)

### Лонг (сигнал «ПОКУПКА»)

Пример: SBER, импульс 250 → 280, цена откатила в зону 50–61.8 % (≈ 261.5–265.4),
стоп за swing low (250), цель 280.

1. Дождитесь сигнала «📈 СИГНАЛ ПОКУПКА — SBER».
2. **Вход**: лимитная заявка на покупку в зоне отката (уровни 50 % / 61.8 % из
   сообщения). Не гонитесь за ценой вне зоны.
3. **Стоп-лосс**: ниже swing low из сообщения (чуть ниже 250, например 248).
4. **Тейк-профит**: на уровне 0 % (цель из сообщения, ≈ 280).
5. Если цена пробила стоп без входа — сигнал считается отменённым, ждём новый
   откат/импульс.

### Шорт (сигнал «ПРОДАЖА»)

Пример: MTSS, импульс 140.5 → 180, цена выкупила вверх в зону 160.25–165.4,
стоп за swing high (180), цель 140.5.

1. Дождитесь сигнала «📉 СИГНАЛ ПРОДАЖА — MTSS».
2. **Вход**: лимитная заявка на продажу в зоне отката вверх (50–61.8 %).
3. **Стоп-лосс**: выше swing high (чуть выше 180, например 182).
4. **Тейк-профит**: на уровне 0 % (цель ≈ 140.5).
5. **Важно**: шорт требует у брокера **маржинальной торговли** (заёмные акции).
   Если у вашего счёта нет маржи — торгуйте шорт-сигналы только лонгами или
   пропускайте.

### Размер позиции

Риск на сделку — **1 % капитала**. Размер позиции:

```
лот = (капитал × 1 %) / (дистанция до стопа в рублях за акцию)
```

Пример: капитал 100 000 ₽, риск 1000 ₽, вход 262, стоп 248 → дистанция 14 ₽ →
лот ≈ 71 акция.

## 6. Автоматическая live-торговля (опционально)

Сейчас в проде включён **dry-run** и не задан `TINKOFF_API_TOKEN` — реальные
ордера не выставляются. Для включения:

1. Получите токен T-Bank Invest API и добавьте в `.env`:
   ```
   TINKOFF_API_TOKEN=t.xxxx
   TRADER_DRY_RUN=false
   ```
2. Для шортов откройте **маржинальный счёт** в T-Bank (брокерский счёт с маржой).
3. Перезапустите контейнер: `docker compose up -d moex-trader`.
4. Откройте `/live` в дашборде:
   - выберите стратегию «Фибоначчи ретрейсмент»;
   - режим «LIVE (реальные ордера)»;
   - кнопка «▶ Запустить».
5. Цикл сам считает сигнал на свежих свечах, ставит стоп/тейк и следит за ними.
   Per-ticker настройки из раздела 3 применяются и здесь.

> Пока токен не задан — live-цикл недоступен, работают только сигналы в
> Telegram и бэктест. Это нормальный режим ручной торговли по разделу 5.

## 7. Риски и предостережения

- **Статистика ограничена**: перебор выполнен на 5-летнем окне дневок, но по
  отдельным бумагам сделок мало (n = 4–22). Результат на будущих данных может
  отличаться.
- **Лонг не подтверждён** перебором — для лонга используйте стандартные
  глобальные параметры и собственный бэктест перед торговлей.
- **Шорт — маржинальная операция**: убыток может превышать первоначальный риск
  при гэпах; требуется маржинальный счёт и понимание механики.
- **Комиссия за перенос позиции за ночь/выходные** (у брокера, напр. 70 ₽/ночь
  при неционале до 100к, пт→выходные = 3 ночи) — удержание шорта до цели
  (2–5 дней) начисляет перенос. Бэктест показал: это ~74% прибыли в худшем
  сценарии ставки, но **EOD-закрытие и ре-вход утром хуже** — теряется
  multi-day хвост прибыли к цели swing low (см. `scripts/backtest_fib_eod.py`).
  Рекомендуется держать позицию до цели (`flat_mode=0`).
- **Сигнал ≠ гарантия**: сообщение описывает готовый сетап, а не приказ.
  Всегда выставляйте стоп-лосс.
- Сигналы и бэктест не являются индивидуальной инвестиционной рекомендацией.

### Объём как подтверждение сигнала — результат диагностики (не активировано)

Проведена диагностика влияния объёма на прибыльность Fib-сигналов
(`scripts/fib_volume_research.py`, причинные фичи строго на баре сигнала, конфиг
совпадает с прод-оверрайдами — паритет 154 шортa 4h, win 61.7%, +63,844 ₽).

Ключевые находки:
- **`bull_bear_in`** (доля быков на баре входа, шорт 4h, Spearman −0.164):
  децильно сильный — шорты с закрытием бара у минимума дают win 87%, у
  максимума 31–53%. Но **портфельный контролируемый бэктест НЕ подтверждает**:
  requiring медвежьего закрытия (`short_need_bear_vol`) снижает итог
  (+63,844 → +48,746/56,487). Причина: отсечённый сигнал не входит и ждёт
  следующий setup (часто хуже), а брекет переякоривается на новую структуру.
- **`vol_rel`/`vol_zscore`** (относительный объём): слабая квадратичная картина
  (золотая полоса 1.5–2.4x, win 80%), но не монотонная и ненадёжная.
- **Exit-тайминг объёмом**: максимальный/средний объём внутри сделки не
  предсказывает отдачу прибыли (win по децилям 46–70%, без монотонности).

**Вывод**: объём не является надёжным предиктором на горизонта 4h. Гейты
`vol_min_rel`, `vol_max_rel`, `long_need_bull_vol`, `short_need_bear_vol`
параметризованы в `_FIB_PULLBACK_PARAMS_TUPLE`, но **по умолчанию выключены
(0) и в прод Оверрайдах не активируются** — прод-поведение не меняется. Их можно
включить вручную через `/fib` (params JSON) для эксперимента, но эмпирически
они не улучшают результат.

### Квантование цены в дискретные уровни — результат диагностики (не внедрено)

Диагностика (`scripts/backtest_fib_quantize.py`): квантование входа/выхода по
дискретным уровням (Фибо-уровни 50/61.8/78.6 и HVN-зоны высокого объёма)
сравнено с базлайном на прод-тикерах 4h шорт (154 сделки, baseline net +22,929):

| Режим | Сделок | Win | Net | Δ vs baseline |
|---|---|---|---|---|
| Baseline | 154 | 61.7% | +22,929 | — |
| Фибо-вход (tol=2.0 ATR) | 150 | 61.3% | +20,094 | −2,835 |
| HVN-вход (tol=0.5 ATR) | 130 | 62.3% | +12,620 | −10,309 |
| Фибо-выход (tol=0.5 ATR) | — | — | −4,400 (T+NLMK) | хуже |

**Вывод**: квантование цены по уровням **не улучшает** результат — только
ухудшает. Прибыль Fib-стратегии идёт от **multi-day удержания до swing low**, а
не от точности точки входа; требование «попасть в уровень» отсекает часть
сделок (HVN: 154→130), не увеличивая прибыль на удержанную позицию. Winning-rate
при этом даже подрастает (62.3% vs 61.7%), но мнимо — покупается за счёт потери
торгового объёма. Квантование **выхода** тоже хуже — урезает multi-day хвост.

Это второй независимый результат (после объёмного гейта): оба подхода к
уточнению входа/выхода не дают преимущества, edge — в удержании. **Не внедрять.**

### Partial take-profit (частичная фиксация) — результат диагностики (не внедрено)

Диагностика (`scripts/backtest_fib_partial.py`): частичный выход на
промежуточном Фибо-уровне поверх удержания до swing low, на прод-тикерах 4h
шорт (154 сделки, baseline net +22,929, risk_pct=1.0):

| partial_frac | at | Net | vs baseline |
|---|---|---|---|
| 0 (baseline) | — | +22,929 | — |
| 0.5 | 50% | +6,895 | −16,034 |
| 0.75 | 50% | −1,175 | −24,104 |

По тикерам partial-тейк **ухудшает 6 из 8** (T, MOEX — исключения из-за очень
длинных хвостов). **Вывод: partial TP НЕ помогает** — фиксирует меньшую прибыль
на победителях (67% сделок доходят до swing low), теряя multi-day tail.

**Риск-скейлинг** (вторичное открытие): риск-скейлинг не масштабируется линейно
с переносом — `risk_pct` 1%→2% → net +22,929→+58,529 (×2.5), т.к. notional при
риске 2% в основном остаётся <100k (70₽/ночь), а gross растёт линейно. Но:
- отдельные тикеры (MOEX 28/30 позиций, GAZP) переваливают 100k → попадают в
  175₽/ночь и уходят в минус при повышенном риске;
- max-DD масштабируется вместе с риском; на едином капитале нужен **портфельный
  бэктест** (сегодня бэктест на отдельных 100k на тикер, что завышает результат
  и не ограничивает одновременные позиции).

**Не внедрять** до портфельного бэктеста на общем капитале с лимитом позиций.

### Корзинка одновременных сигналов (вход во все + выход по первому TP) — не работает

Диагностика (`scripts/backtest_fib_basket.py`): собраны все шорт-входы 8 тикеров
4h (154 сделки) и сгруппированы по одновременности (один 4h-бар / тот же день /
окно N-баров), затем — вход во все как в корзину и закрытие всех при первом
достижении тейка (swing low). Сравнение с независимым выходом (baseline
net +22,929):

| Ось | Корзин ≥2 | each_tp (незав.) | **Выход по первому TP** |
|---|---|---|---|
| бар | 12 | +7,557 | **−5,941** |
| день | 37 | +12,633 | **−21,672** |
| окно 2 | 21 | +11,019 | −705 |
| окно 3 | 25 | +10,926 | −46 |
| окно 4 | 23 | +7,550 | −2,942 |

**Вывод: выход всей корзинки по первому тейку разрушает прибыль** (день: +12,633
→ −21,672, потеря −34k). Хотя gross даже больше, перенос взлетает (17,500 →
41,650): «первый тейк» часто происходит поздно → остальные переносятся дольше, а
закрываются раньше своего тейка → теряют индивидуальный multi-day хвост.

**«Одновременность» ≥3 на одном 4h-баре отсутствует** (0 корзин за 13 мес; максимум
2 на баре, 12 случаев). Реальные совпадения — только на уровне дня/окна («общий
рыночный день», win всего 56%), а это худшие корзинки.

**Не внедрять.** Это гарантирует: edge — строго в независимом удержании каждого
тикера до собственного тейка.

### Эксперименты v2 (E1–E5) — поиск прибыльной модификации (2026-09)

входа, тренд-фильтр, риск-инженерия, сетка с OOS по эрам (мир ≤2022-02-24 /
война). Добавлен параметр удержания `run_backtest(hold_days=N)` (один фейд-вход
на N свечей вместо мартингейла) — опция в веб-форме.

  неровный (T +2.80M и SBER +0.52M против GAZP −0.96M, LKOH −0.62M, MTSS −0.40M).

**Общий вердикт v2**: крупной прибыльной модификации НЕ найдено; ранний
«сильный» результат q≥0.8+3д оказался артефактом ошибки в диагностике
(шорты считались как лонги) и после исправления свёлся к уже известному тонкому
краю качества. Практически полезное: (1) риск-инженерия — без 3-го шага
мартингейла maxDD ~3× ниже при сопоставимом net (q≥0.6 «2 шага+стоп» лучший
risk-adjusted вариант из протестированных); (2) `hold_days` как инструмент
сравнения горизонтов в прод-бэктесте/веб-форме. Для live по-прежнему не
подтверждено.

**Почему убыток, а не только при 7 свечах подряд** (частое заблуждение):
сигнал срабатывает на закрытии 3-й свечи серии, вход — на open следующей. Если
ряд ПРОДОЛЖАЕТСЯ, fade проигрывает шаг уже на 4–6 свечах. По итоговой длине
серии (по всем тикерам): len=3 → 0% проигрышей step1, len=4 → 50%, len=5 → 67%,
len=6+ → 100%. Серии из 6+ свечей не редкость (~170+ за историю). «Для убытка
нужны 7 свечей» верно только для ПОЛНОЙ гибели 3-шагового мартингейла, а такие
ряды (6–8) случаются регулярно. Ошибка — в допущении, что на 3-й свече известно,
кончился ли ряд: выигрыш 98% достижим лишь при входе на свече, про которую цвет
известен задним числом (lookahead, см. выше).

**Ограничение на 3 прибыльные бумаги** (2026-09): по всем конфигурациям стабильно
прибыльны SBER и T; третья — NLMK (классика q≥0.8) или TATN (hold_days=3).
Решение: Elliott-скан ограничен **SBER, T, NLMK** через `TRADER_ELLIOTT_TICKERS`
(default, см. `config.py`/`.env.example`); пустое значение возвращает старый
режим «весь watchlist». Прочее не подтверждено — вне скана.

**Требование «сильного импульса» в волне** (2026-09): волна должна содержать
1–2 свечи с телом ≥ k×ATR(14) (параметры `impulse_strong_k`/`impulse_strong_min`
в `run_backtest`, веб-форме и notifier-гейте `TRADER_ELLIOTT_STRONG_ATR_K`,
по умолчанию выключен в live). Проверка на движке (10 тикеров, 10M/тикер,
комиссия 0.09%/сторона):
- 1-шаг q≥0.6: база net +1,396,969 (n=532) → с k=1.0, ≥1 сильной свечой
  net +1,703,732 (n=336, win 53.0%);
- классика-мартингейл q≥0.6: база +3,016,133 → с k=1.0 net **+4,670,420**
  (n=317, win 74.8%); обе эры положительны (мир +0.34%, война +0.22%);
- важная оговорка: фильтр сильных свечей помогает 1-дневному фейду и
  мартингейлу, но ВРЕДИТ много-дневному удержанию (q≥0.8 hold_days=3 с k=1.0
  → минус): сильные свечи = продолжение тренда, откат происходит за 1 день.
- пороги (q, k, min) подобраны in-sample — возможен перефит; для live не
  включено по умолчанию.

**Лонг-only** (2026-09, лучший сбалансированный вариант): фейд только в лонг
(медвежья волна → BUY), комиссия по лонгу ниже. Реализация: параметр движка
`run_backtest(direction=1)` (0=обе, 1=лонг, 2=шорт), веб-форма (default 1),
notifier-гейт `TRADER_ELLIOTT_LONG_ONLY` (default true — шорт-сигналы не шлются).

- 117 сделок, win 62.4%, net +0.539%/сделку (net ~+1.58M на 25%); движок

- по эрам: мир +0.568% (win 71%), война +0.525% (win 58%) — СИММЕТРИЧНО (шорт

**4h-таймфрейм — НЕ переживает** (2026-09). Проверено на тех же 9 тикерах,

### Fib-расширения как цель/стоп (реальный бэктест) — почему Фибоначчи "работает" не везде

Диагностика (`scripts/backtest_fib_targets.py`, реальный backtrader-бэктест с
параметрами `fib_target_mult` / `fib_stop_mult`, default 1.0 = прод). Шорт 4h,
8 тикеров. Паритет baseline подтверждён: tm=1.0/sm=1.0 → n=154, gross +63,844,
net +22,929.

| вариант | n | win | gross | carry | net |
|---|---|---|---|---|---|
| **цель=1.0 (swing low)** | 154 | 61.7% | +63,844 | 40,915 | **+22,929** |
| цель=1.272 (Fib ext) | 158 | 58.2% | **+67,159** | 46,095 | +21,064 |
| цель=1.618 (Fib ext) | 160 | 54.4% | +44,782 | 49,665 | −4,883 |
| стоп=1.272 | 159 | 61.6% | +52,691 | 45,115 | +7,576 |
| стоп=1.618 | 158 | 56.3% | +8,321 | 38,115 | −29,794 |

**Главное наблюдение**: цель Fib 127.2% даёт БОЛЬШЕ gross (+67,159), но лишняя
прибыль съедается переносом (46,095) — net чуть ниже. Цель 161.8% — уже убыток:
цена редко доходит, победители превращаются в перенос-пожирателей. Стоп шире —
резко хуже. **Вывод: расширение цели за swing low не улучшает net.**

**Почему Фибоначчи "работает" в одних случаях и нет в других** — 8 причин,
подтверждённых нашими 9 экспериментами:
1. **Затраты переноса/комиссии**: тонкий край (+0.1–0.4%/сделку) умирает от
   70/175 ₽/ночь и 0.1% комиссии. Fib-уровни дают край меньше издержек.
2. **Удержание vs отбор**: прибыль Fib-шорта идёт от multi-day хвоста до цели;
   любой фильтр (объём/квантование/корзинка/SMA200/Elliott/MTF-Fib) режет net.
3. **Режим рынка**: война 2022–2026 → шорт-плечо работает, лонг убыточен.
   Fib-лонг "не работает" во многом потому, что рынок падал.
4. **Таймфрейм**: 4h-шорт прибылен, 1day-шорт убит переносом (больше ночей).
5. **Точка применения**: уровни как ЦЕЛЬ/сток — работают (swing low), как
   ФИЛЬТР входа — режут. Fib != вход-фильтр.
6. **Малый размер выборки**: 29–154 сделки; win-rate 62% на 8 сделках — шум.
7. **Lookahead**: Elliott-бэктест давал 98% win из-за тавтологии; сделки MTF —
   из-за lookahead дневного бара. Реальные края всегда скромнее.
8. **Ликвидность/капитал**: на 10M лотах 2.5–10M нецинал не влезает без слайпеджа.

**Что учитывать**: считать net (комиссия+перенос+слайпедж), проверять без
lookahead, разделять режимы, требовать достаточную выборку, и не применять
Fib-уровни как вход-фильтр (только как структурные цель/стоп).

### Pyramiding (добавки к шорту на коррекциях) — ухудшает

Идея: после 4h-сигнала не фильтровать вход, а добавлять к шорту на отскоке
(коррекции) — средний вход улучшается, цель/стоп структурные. Реализовано в
`FibPullbackStrategy` параметрами `fib_pyramid_frac`/`fib_pyramid_max`/
`fib_pyramid_trigger` (default 0 — прод не меняется), стоп/тейк фиксируются на
первом входе (не «ползут»). Реальный бэктест `scripts/backtest_fib_pyramid_real.py`:

| вариант | n | win | gross | carry | net |
|---|---|---|---|---|---|
| **baseline** | 154 | 61.7% | +63,763 | 40,915 | **+22,848** |
| любой отскок, 0.25×1 | 156 | 56.4% | +37,583 | 35,315 | +2,268 |
| любой отскок, 0.5×1 | 156 | 55.8% | +32,488 | 36,015 | −3,527 |
| разворотная 2h-свеча, 0.25×1 | 146 | 57.5% | +42,145 | 33,425 | +8,720 |
| Fib-зона 50–78.6%, 0.25×1 | 161 | 57.1% | +45,821 | 34,335 | +11,486 |
| Fib-зона 50–78.6%, 0.5×1 | 161 | 57.1% | +45,998 | 34,335 | +11,663 |

- **Все варианты pyramiding хуже baseline** (+22,848 → +2,268…+11,663). Refined
  триггеры (разворотная свеча, Fib-зона) менее плохи, но всё равно режут net.
- Главный источник потерь — **MOEX** (baseline +1,109 → −18,524 при добавках):
  частые отскоки выше входа, после которых цена идёт к стопу, увеличенная
  позиция теряет больше.
- **Вывод: добавки на коррекциях не улучшают Fib-шорт.** Девятый подряд результат
  «улучшение входа/размера режет net»: edge — в неизменном удержании позиции до
  цели, а не в усреднении.
- Побочный эффект реализации (исправлено): при добавке нельзя пересчитывать стоп
  от цены добавки и нельзя оставлять старые брекет-ордера — иначе двойное
  покрытие. Стоп/тейк фиксируются на входе.

⚠️ **Режим рынка**: весь период тестирования (2022–2026) — военное время,
MOEX в нисходящем/боковом тренде. Это благоприятно для шорта и неблагоприятно
для лонга. Если рынок перейдёт в устойчивый восходящий тренд (например, после
завершения войны) — **повторить тестирование и шорта, и лонга**: шорт-край может
ослабнуть, лонг может ожить.

### Kinetic Momentum (импульс + кинетическая энергия) — не подтверждена

Новая стратегия по чистой математике/физике на OHLCV (`app/kinetic.py`,
`scripts/backtest_kinetic.py`, реализована 2026-09). Модель: цена как частица
с количеством движения `P = Σ m·v` (m — относительный объём, v — лог-доходность
в единицах волатильности σ=EWMA-стд) и кинетической энергией `KE = Σ m·v²`.
Импульс нормирован в z-единицы (`Pz = P/(std(p)·√mom_span)`), вход — при
`|Pz| ≥ θ` и расширяющейся KE (KE > базиса за `ke_span`), выход — при развороте
Pz или «диссипации» энергии (охлаждение `cool_bars` подряд). Инерция по
I закону Ньютона: пока энергия расширяется — тело сохраняет движение.

Проверка live-faithful (сигнал на закрытии бара, вход/выход на open следующего,
комиссия 0.05%/сторона + слайп 0.05%, риск 1%, лот от ATR-стопа; интрадей-данные
SBER 1/5/30/60min, NVTK 15min, T 60min, ~1 год 2025-08..2026-08):

| ТФ (тикер) | n | win (с затратами) | net без затрат | net с затратами |
|---|---|---|---|---|
| 1min (SBER) | 3552 | 5.3% | −25.9% | **−99.9%** |
| 5min (SBER) | 752 | 13.2% | −25.0% | **−82.0%** |
| 15min (NVTK) | 275 | 24.7% | −34.2% | **−60.8%** |
| 30min (SBER) | 120 | 25.8% | +8.5% | **−13.6%** |
| 60min (SBER) | 64 | 39.1% | +12.0% | **−0.7%** |
| 60min (T) | 80 | 35.0% | — | **−5.9%** |

- **Raw-края нет на быстрых ТФ**: даже при нулевых затратах 1/5/15min дают минус
  (−25…−34%) — сигнал на внутридневном шуме отрицателен сам по себе (тот же
  военный режим, что убивает лонг/тренд). Плюс на 30/60min (+8.5/+12% gross) —
  тонкий и целиком съедается комиссией+слайпом (круг ~0.2%): при реалистичных
  затратах все варианты в минусе.
- **Grid по параметрам** (mom_span×ke_span×θ×direction×cool_bars×min_hold,
  324 комбинации, обе половины истории должны быть прибыльными с затратами):
  **0 подтверждённых конфигураций** на SBER 30min/60min и T 60min.
- Win-rate с затратами 5–39% против 44–51% у random-control: на шуме сигнал
  хуже случайного выбора моментов.

**Вывод: НЕ подтверждена.** Стратегия оставлена в коде для экспериментов
(реестр `STRATEGIES["kinetic"]`, SIGNAL_FUNCS), но не включена в прод-нотификатор
и не рекомендована к торговле. Паттерн тот же, что у SMA200/Elliott/SMA-cross:
на интрадее издержки (0.2% на круг) превышают любой сырой край, а момент-края на
MOEX 2022–2026 (военный нисходящий режим) на коротких горизонтах нет. Если рынок
перейдёт в устойчивый восходящий тренд — повторно прогнать `backtest_kinetic.py`
(особенно лонг 60min, где gross-край был максимальным).

**Проверка «только лонг» (2026-09, `--direction 1`)** — тоже не подтверждена:

- **Интрадей (SBER 1/5/30/60min, NVTK 15min, T 60min)**: net с затратами
  −95.5% / −54.6% / −38.5% / −6.6% / −0.4% (SBER 60min) / −3.4% (T 60min).
  Лучший — лонг SBER 60min (0-cost +5.4%, с затратами −0.4%, n=30). Grid лонг-only
  (162 комбинации, 60min/30min): **0 конфигураций**, прибыльных на обеих половинах.
- **Дневки (1day, 10 тикеров 2021–2026)**: суммарно −1.8%; в плюсе лишь SBER
  (+5.1%), NVTK (+3.4%), NLMK (+2.4%) при маленьких выборках (n=8–43). Ключевой
  тест OOS: **train (1-я половина) +33.0%, test (2-я половина) −23.7%** — весь
  лонг-плюс сидит в старом бычьем периоде, на свежих 2.5 годах убыточен. Тот же
  результат, что и у SMA200-лонга и Elliott long: на 2022–2026 (военный режим)
  лонг не работает.

### Multi-Timeframe Confirmation (часовой сигнал + дневной зона-фильтр) — НЕ ПОДТВЕРЖДЕНА

⚠️ **КРИТИЧЕСКИЙ БАГ LOOKAHEAD (исправлен 2026-09):** `htf_state_at` в
`app/mtf_confirm.py` использовал дневной бар с begin=00:00 UTC текущего дня для
интрадей сигналов (04:00/08:00/12:00 UTC). В бэктесте close этого дневного бара —
это конец торгового дня (future data). Из-за этого все предыдущие результаты
(+139%, +150% и т.д.) **инфлированы lookahead и недействительны**.

В production MOEX daily bar обновляется интрадей (close = последняя цена на момент
синхронизации), поэтому production нотификатор **causal**. Но бэктест больше не
может валидировать стратегию — исторические дневные close в БД — это концы дней.

**Исправление**: добавлен параметр `causal_daily` в `htf_state_at`/`mtf_signal`/
`mtf_stats`. Backtests теперь используют `causal_daily=True` (только завершённые
дневные бары). Production `mtf_notifier.py` оставлен `causal_daily=False`.

**Честные результаты (causal_daily=True, 4h, zone_break, сигналы 4/8/12 UTC):**

| Конфиг | сделок | win_net | pnl% | pos | 1st half | 2nd half |
|---|---|---|---|---|---|---|
| Baseline close+6 | 106 | 45.8% | **−34.33%** | 4/9 | 44.6% −16.41 (2/9) | 45.4% −6.21 (4/9) |

**Статистика (causal, 4h, zone_break, horizon 6):**

| label | side | n | win% | base% | z |
|---|---|---|---|---|---|
| confirmed | bear | ~110 | ~49% | ~52% | ≈ 0 |
| no_filter | bear | ~280 | ~49% | ~52% | ≈ −1 |
| confirmed | bull | ~55 | ~45% | ~47% | ≈ −0.5 |

**Вердикт: НЕ ПОДТВЕРЖДЕНА**. Без lookahead зона-фильтр не даёт edge. Стратегия
теряет деньги. **Не торговать по MTF-сигналу на основе backtest'а.**

**Почему production может быть другим:** MOEX ISS daily candle обновляется
интрадей (close = текущая цена), поэтому production использует causal daily state.
Однако мы **не можем это валидировать** на исторических данных. Рекомендация:
- Остановить MTF-нотификатор ИЛИ
- Вести paper-trading ≥3 месяцев с фиксацией результатов ИЛИ
- Найти другую, валидную без lookahead стратегию

**Внедрение в прод (текущее состояние):**

- Модуль: `app/mtf_notifier.py`
- Дедуп: таблица `mtf_signals` (ticker + signal_ts + side)
- Расписание: скан в 08:00, 12:00, 16:00 UTC
- Data sync: `mtf_data_sync_task` каждые ~6ч
- Тикеры: `TRADER_MTF_TICKERS` — 8 тикеров
- Часы сигнала: `TRADER_MTF_SIGNAL_HOURS` = [4,8,12] UTC
- **Elliott TP в сообщении**: если найдена волна 1-2, указывается TP-цена; иначе baseline close+6
- Автоторговли нет — только уведомления

**Конфиг Elliott TP в сообщениях:**
- `TRADER_MTF_ELLIOTT_TP_ENABLED=true`
- `TRADER_MTF_ELLIOTT_K=1.618`
- `TRADER_MTF_ELLIOTT_TIME_CAP=12`
- `TRADER_MTF_ELLIOTT_WAVE_TF=1day`
